# 計画書: JSONレポート出力(v1.0)

## 目的

現在の「レポート作成」はMarkdown固定で人が読む用途向け。スキャン結果を他ツール・スクリプトから機械的に読み込みたい場合のために、同じスキャン結果をJSON形式でもエクスポートできるようにする。Markdown出力は変更しない(追加のみ)。

## 現状分析

- `static/js/app.js:555-590`
  - `generateMdReport(root, scanTime)`: `scanTree`(ネストしたノードJSON)からMarkdown文字列を組み立てる
  - `onExportReport()`: Markdownを生成し、`{cmd:'export_report', content, default_name}` をネイティブへ送るだけ。`content`はネイティブ側で書き込むだけの不透明な文字列
  - メニュー項目は `index.html:17` の `id="act-report" data-action="report"`(ショートカット `Ctrl+Shift+S`)の1つのみ。スキャン未完了時は `disabled` クラスで無効化(`app.js:612-614 setReportEnabled`)
- `core/native/webview_main.cpp`
  - `ShowSaveFileDialog()`(316行目): `COMDLG_FILTERSPEC` が `Markdown Files (*.md)` / `All Files (*.*)` に固定
  - `HandleExportReport(content, default_name)`(548行目): 中身を見ずUTF-8でそのままファイル書き込みするだけ。フォーマット非依存
  - `export_report` コマンド受信部(835行目付近): `content` と `default_name` の2パラメータのみ受け取る
- `scanTree` はスキャン完了時に `scan_finished` で受け取るネストしたノードJSON(`name/path/size/file_count/mtime_ms/is_accessible/is_dir/children`)をそのままJS側で保持している(`spec_jp.md` 5節のノードJSON形式と同一)

## 変更内容

### 変更するファイル

1. **`static/js/app.js`**
   - `generateJsonReport(root, scanTime)` を新設。出力形式:
     ```json
     {
       "path": "C:\\path\\to\\folder",
       "scanned_at": "2025-01-15T10:30:00+09:00",
       "total_size": 1288490188,
       "subfolder_count": 42,
       "file_count_recursive": 1234,
       "tree": { "name": "...", "size": 0, "file_count": 0, "is_dir": true, "is_accessible": true, "children": [...] }
     }
     ```
     `tree`は`scanTree`をそのまま(`path`は循環しないよう相対名だけ残すか要検討 → 今回はルート以外`path`省略し軽量化する)
   - `onExportReport(format)` に引数追加(`'md'` | `'json'`)。`format`に応じて生成関数・`default_name`拡張子(`report_YYYYMMDD_HHMMSS.md` / `.json`)を切り替え、`export_report`コマンドに `format` を追加して送信
   - `case 'report'` と並べて `case 'report_json'` をメニューハンドラに追加(658行目付近)
   - `Ctrl+Shift+S` は既存のMarkdown出力のまま変更しない(JSONは新規メニュー項目のみ、ショートカット無し)
   - i18n(`I18N`テーブル)に `act_report_json: { ja: 'レポート作成(JSON)...', en: 'Export Report (JSON)...' }` を追加

2. **`templates/index.html`**
   - `id="act-report"` の直後に `id="act-report-json" data-action="report_json"` の行を追加(同じく `disabled` クラス初期状態、`data-i18n="act_report_json"`)
   - `setReportEnabled()` は両方のIDを同時にトグルするよう `app.js` 側を修正

3. **`core/native/webview_main.cpp`**
   - `ShowSaveFileDialog()` の `COMDLG_FILTERSPEC` に `{ L"JSON Files (*.json)", L"*.json" }` を追加し、`default_name` の拡張子から `SetFileTypeIndex` で初期選択フィルタを切り替える
   - `HandleExportReport` 自体はフォーマット非依存のため変更不要(中身は見ない)。`export_report` コマンド受信部は既存の `content`/`default_name` のみ使用し続ける(`format` パラメータはUI側の分岐にのみ使うため、ネイティブに渡す必要はない)

4. **`document/spec_jp.md` / `document/spec.md`は対象外(spec.mdは現状未作成)**
   - `document/spec_jp.md` 4節(機能一覧)・5節(WebMessageプロトコル)・8節(Markdownレポートフォーマット仕様)に、JSON出力の追加を反映(9節としてJSON仕様を追記)

5. **`resources/help/help_jp.md` / `resources/help/help.md`**
   - 7節「レポートを作成する」にJSON出力の説明を追記(メニュー2項目に分かれる旨、用途の違い)

### 変更しないもの

- Markdown出力の内容・フォーマット・ショートカット(`Ctrl+Shift+S`)
- `export_report` コマンドの `content`/`default_name` パラメータの意味(ネイティブは引き続きフォーマット非依存)
- スキャンエンジン(`engine.cpp`)・WebMessageプロトコルの他コマンド
- 既存のMarkdownレポート保存ダイアログの挙動(ファイル名を手動で`.json`に変えて保存すればMarkdown出力でも動作する、という現状の緩さはJSON追加後も維持)

## 検証方法

1. `build.bat` でビルドが通ること(エラー・警告なし)
2. スキャン完了後、メニュー「ファイル」に「レポート作成...」と「レポート作成(JSON)...」の2項目が表示され、スキャン未完了時は両方disabledになること
3. 「レポート作成(JSON)...」を実行し、保存したファイルをテキストエディタで開いて妥当なJSON(`JSON.parse`可能)であること、`total_size`等のトップレベル値が画面表示と一致すること
4. 既存の「レポート作成...」(Markdown)が変更前と同じ内容で出力されること(回帰確認)
5. 日本語/English切替時、両メニュー項目とファイルダイアログのフィルタ名が正しく切り替わること
6. 保存ダイアログでキャンセルした場合、両フォーマットとも何も起きないこと(既存挙動の踏襲確認)

## リスク

- `scanTree`のノード数が多い巨大フォルダをJSON化すると、Markdownより数値の桁が多く出力ファイルサイズが大きくなる可能性(圧縮や省略はしない前提。必要なら別途検討)
- `path`をノードごとに含めるとルートパスの重複でファイルサイズが増える。省略設計にする場合、外部ツール側で親パスから絶対パスを復元する必要が生じ、Markdown版より使い勝手が落ちる可能性(→この設計判断は承認時に確定させたい)
- ネイティブ側の保存ダイアログにフィルタを追加する際、`SetFileTypeIndex`の指定を誤ると初期選択フィルタが意図と異なるものになる可能性(検証項目3で確認)
- 既存の`Ctrl+Shift+S`ユーザーの操作性に影響しないよう、JSON側にショートカットを割り当てないため、キーボードのみでのJSON出力ができない(必要であれば別ショートカット案を追加で検討)
