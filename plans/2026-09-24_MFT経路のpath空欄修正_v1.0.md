# MFT経路でpathが空文字になる不具合の修正

## 不具合の記録（2026-09-24 報告）

- 現象: `dist\QuickFolderSize_cli.exe`（v3.1.0）を管理者権限で `QuickFolderSize_cli.exe C:\` と実行すると、出力JSONのトップレベル `"path"` と `tree` 内の全ノードの `"path"` が空文字 `""` になる。`name`・`size`・`file_count` などは正常。
- 条件: 管理者権限時はエンジンがNTFS MFT列挙を使う。非管理者時はWin32列挙にフォールバックし、こちらは正常。

## 調査結果

- `src/engine/engine.cpp` の `TryScanNtfsMft()` が `BuildEntryFromMft(5, drive_root, ..., include_paths=false)` を呼んでおり、MFT経路では全ノードの `EntryBuilder::path` を意図的に `L""` にしていた（GUI表示用JSONはパスを送らずJS側で復元するため、125万件分のパス文字列生成を省く最適化）。
- CLI（`src/cli/main_cli.cpp` の `SerializeEntryJson`）は `node.path` をそのまま出力するため空になる。
- GUI（`src/app/main_gui.cpp`）も同じ影響を受ける:
  - 画面表示: `compact_paths`/`flat_records` 形式でパスを送らないため影響なし。
  - 「レポート作成(JSON)」`BuildJsonReport`: トップレベル・全ノードの `path` が空。
  - 「レポート作成(Markdown)」`BuildMdReport`: 「パス」欄が空。

## 修正方針

- MFT経路でも各ノードにフルパスを設定する（`include_paths=true`）。ルートは `C:\`、子は `親パス + \ + 名前`（Win32経路と同形式: ディレクトリ末尾に `\` を付けない）。
- GUI表示用JSONは従来どおりパスを送らないため、画面表示への影響はパス文字列生成分の時間・メモリのみ。`mft_build_ms` を修正前後で計測して記録する。

## 検証項目

1. CLIを再ビルドする。
2. 昇格実行（`Start-Process cmd -Verb RunAs`、stdoutはファイルへリダイレクト）で `C:\` をスキャンし、`scan_mode`=MFT経路で `path` が埋まっていることを確認する。
3. 非管理者（Win32経路）でも `path` が従来どおり正しいことを確認する。
4. GUIをビルドし、ビルドが通ることを確認する。

## 結果（2026-09-24、別セッションから引き継いで検証）

- 修正（`include_paths=true`）は採用。拡張レコード等の修正（plans/2026-09-24_MFT拡張レコード無視によるサイズ欠落_調査_v1.0.md）と合わせて `scripts/build.py` で GUI・CLI ともビルド成功。
- 昇格実行で C:\ をスキャン: トップレベル `path` は `C:\`、全ノードで `path` が空のものは 0 件、`親パス + \ + 名前` との不一致も 0 件。
- 非管理者（Win32 経路）でテスト用フォルダと OneDrive フォルダをスキャン: `path` は従来どおり正しい。
- `mft_build_ms` の修正前後比較は未計測（CLI は scan_mode や時間を出力しないため）。昇格実行の所要時間は修正前 48〜52 秒、修正後 52 秒でほぼ同じ。
