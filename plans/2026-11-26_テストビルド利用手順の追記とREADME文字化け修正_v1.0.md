# 計画書: テスト用ビルドの利用手順の追記と README の制御文字修正(v1.0)

## 依頼・指摘

- 2026-11-26、ユーザーから「じゃあ、次使うときはどうするの？」との質問を受けた。
- 調べたところ、テスト用ビルドの作り方は README にあるが、**auto-window から UI テストを実行する手順(管理者ターミナルが必要なこと等)はどこにも書かれていない**ことが分かった。
- あわせて、PR #19 で README.md / README_jp.md に追記した行に不具合を見つけた。`scripts\build.bat` の `\b` がバックスペース制御文字(0x08)に変換されていて、
  `scripts<BS>uild.bat` と壊れて表示される(各ファイル1か所。od で確認した)。

## 変更内容

1. README.md / README_jp.md の制御文字を `scripts\build.bat` に直す。
2. 同じ節に、テスト用ビルドで UI テストを実行する手順を追記する。
   - テスト用 exe のビルド(ソースを変えたら作り直す)
   - **管理者の PowerShell** で、auto-window のリポジトリ直下から `SCAN_PATH` を設定してタスクを実行する
   - 管理者でないターミナルから実行すると、UAC の確認で止まる(理由)

## 検証

- 両 README に制御文字(0x08)が0件であること。
- 書いた手順のコマンド・パスが、実ファイル(build.bat の引数の受け渡し、タスクファイルのパス)と一致していること。

## 追加指示(2026-11-26): 全部コミット・タグ付きプッシュ

- ユーザーから「全部コミット・タグ付きプッシュ」との指示があった。確認した結果は次のとおり。
  - QuickFolderSize のタグは **v3.2.1**(パッチリリース)。v3.2.0 以降の変更は PR #19 と PR #20、今回のドキュメント修正。
    配布版の動作で変わるのは「管理者として起動し直すとき、起動引数を引き継ぐ」修正だけ。
  - auto-window にはタグを付けない。
- 手順:
  1. 3.2.0 と書かれている箇所(exe のバージョン情報・HISTORY・README・docs・ヘルプ・UI)を 3.2.1 に更新し、HISTORY に v3.2.1 の内容を追記する。
  2. 通常ビルドして、exe のバージョンが 3.2.1 になっていることを確認する。
  3. PR を作り、CI が通ったらマージする。そのあと main に `v3.2.1` の注釈付きタグを付けて push する。push すると release.yml が動く。
  4. release.yml の成功と、GitHub Release に配布物が上がったことを確認する。
