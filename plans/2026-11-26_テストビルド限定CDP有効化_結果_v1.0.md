# 結果報告: テスト用ビルドに限定したCDP(リモートデバッグ)有効化(v1.0)

対象計画書: [2026-11-26_テストビルド限定CDP有効化_v1.0.md](2026-11-26_テストビルド限定CDP有効化_v1.0.md)

## 実施内容

1. `src/app/main_gui.cpp`
   - `#include <shlwapi.h>` を追加した。
   - `EnsureAdministrator()`: `lpParameters = PathGetArgsW(GetCommandLineW())` で起動引数を引き継ぐようにした(全ビルド共通)。
   - `#ifdef QFS_ENABLE_CDP` の中に、次を追加した。
     - `ICoreWebView2EnvironmentOptions` を実装した最小限のクラス `QfsEnvOptions`(IIDは自前で定義、TargetCompatibleBrowserVersion は `151.0.4129.50`)
     - `ParseRemoteDebuggingPort()`(1024〜65535 の数字だけを受け付ける)
   - ユーザーデータフォルダ: テスト用ビルドは `QuickFolderSize_test_WVData`、配布版は従来どおり `QuickFolderSize_WVData`。
   - `createEnv` の第3引数に `envOptions` を渡す(配布版では常に nullptr)。呼び出し後に Release する。ログに `[CDP] ...` を出す。
2. `scripts/build.py`
   - `--test-build` で `-DQFS_ENABLE_CDP` を付け、`build/test/QuickFolderSize_test.exe` と `WebView2Loader.dll` を出力するようにした(dist には出力しない)。
   - GUI のリンクに `-lshlwapi` を追加した。WebView2Loader の探索は `find_webview2_loader()` に分けた(テスト用ビルドだけで使う)。

## 検証結果

### ビルド
- `python scripts/build.py --test-build`: 成功(3,906,552 bytes)。実行の前後で `dist/QuickFolderSize.exe` のバイト列が変わっていないことを cmp で確認した。
- `python scripts/build.py`(通常): GUI と CLI のビルドに成功した。
  - 配布版の exe には、UTF-16 の `remote-debugging` と `QuickFolderSize_test` が **0件**。CDP のコードが入っていないことを確認した。
  - テスト用 exe には UTF-16 の `remote-debugging` が含まれていることを確認した。
- `build/` と `*.exe` は `.gitignore` の対象(バイナリはコミットされない)。

### 実機検証 1回目(2026-11-26 12:24、AIの管理者でないシェルから実行) → 不成立

- 計画では「管理者ターミナルでユーザーが実行する」としていたが、AIが管理者でないシェルから auto-window のタスクを実行した(計画からの逸脱)。
- テスト用 exe(PID 26992)は管理者として起動し直すため UAC の確認を出し、`ShellExecuteExW` で許可待ちのまま止まった。
  `consent.exe`(PID 20640、12:24:41起動)が残っていたことで確認した。テスト用 exe のデバッグログは作られていない(WinMain まで進んでいない)。
- 60秒でタイムアウトし、auto-window が PID 26992 を終了した。UAC のダイアログは画面に残った。
  → ユーザーに「いいえ」を押してもらうよう依頼する(許可すると、CDP が開いた管理者のアプリが誰にも終了されずに残るため)。
- 分かったこと: この端末の UAC は確認ダイアログを出す設定なので、管理者でないプロセスからの自動テストでは、毎回人の操作が必要になる。
  **自動テストは管理者ターミナルから実行するのが前提**になる(その場合は起動し直さないので、起動したPIDがそのままアプリ本体になり、終了処理も効く)。

- 1回目の後処理: ユーザーが UAC で「いいえ」を選んだ。その後、QuickFolderSize の残存プロセスと consent.exe はいずれも0件だった。

### 実機検証 2回目(2026-11-26 12:27、ユーザーが管理者PowerShellで実行) → **合格**

`python -m auto_window run python/tasks/quickfoldersize_cdp_check.yaml`(auto-window 側、`cdp_launch: arg`)を実行した。

- 起動からCDPの応答確認までの所要時間: 約1.6秒(12:27:56 起動 → 12:27:57 応答、PID=20524)。
- 9ステップすべて OK、タスクは「成功」。
  - wait → fill(`templates` のパス、58文字)→ click(スキャン)→ wait(`#tree-body tr`)
  - assert_text(`static` が含まれる)→ evaluate(行数=3)→ screenshot → evaluate(`quit` を送信)
- アプリのデバッグログ: `[7] User data folder: ...QuickFolderSize_test_WVData`、`[CDP] enabled port=9222`、
  `[SCAN] method=win32 ...`、`[14] Exiting WinMain`(quit で正常に終了した)。
- スクリーンショット `auto-window/logs/quickfoldersize_cdp_check.png` を目視で確認した。アドレス欄に templates のパスがあり、
  static(25.9 KB、78.4%)/ index.html / screenshot_window.html の3行と、スキャン完了(0.04s)が表示されていた。
- 実行後の残存: QuickFolderSize 系のプロセス0、そのアプリの msedgewebview2 も0、consent.exe も0。
- ログに出た `プロセス(PID=20524)の終了に失敗: not found` は、quit でアプリが先に終了していたためで、問題はない。
  auto-window 側で「すでに終了していれば taskkill しない」ように修正した(テストを1件追加、87 passed)。
