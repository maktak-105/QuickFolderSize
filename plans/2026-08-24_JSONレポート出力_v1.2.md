## 現状分析

### A/B/C

v1.1のまま(変更なし)。

### D. CLI版

- `core/native/engine.h`のAPI(`scan_directory()` / `ScanEntryC`)は元々GUI非依存のC互換関数で、GUI用に`webview_main.cpp`が薄くラップしているのと同じ形でCLI用ラッパーを書ける
- `core/native/main_cli.cpp`は**まだ存在しない**(確認済み、`ls`で該当なし)。テンプレート([01_フォルダ構成.md](file:///C:/Users/0120025-Z100/.claude/skills/quick-app-template/01_フォルダ構成.md))には「`main_cli.cpp` CLI版エントリーポイント(不要なら省略可)」として元々予約枠がある
- GUI版は`QuickFolderSize.rc`経由で`requireAdministrator`マニフェストを埋め込んでおり、起動のたびにUACを要求する(`webview_main.cpp`の`EnsureAdministrator()`)。CLIを同じ方式にすると、AIエージェントやスクリプトからの非対話実行(パイプ・自動化)がUACダイアログでブロックされてしまう
- `engine.cpp`のMFT高速経路(`TryScanNtfsMft()`)は、`\\.\C:`を`CreateFileW`で開けない場合(非管理者権限など)は`MftScanResult::Unavailable`を返し、自動的にWin32列挙(`FindFirstFileW`/`FindNextFileW`)へフォールバックする既存動作がある(`spec_jp.md`6節で確認済み)。つまり**CLIに管理者権限が無くてもクラッシュせず、単に低速経路で動く**
- README.mdの「Concept」節に「Export the report and feed it to an AI agent」という記述が既にあり、AI活用は元々このプロジェクトの想定用途として明記されている
- `dist/documents/readme.txt`/`readme_jp.txt`には現状GUI版の使い方のみ記載、CLIに関する記述はゼロ
- `build_native.py`のGUIビルドコマンド(`cmd_gui`)は`-mwindows`(GUIサブシステム、コンソール無し)。CLIは逆に`-mwindows`を付けない通常のコンソールサブシステムとしてビルドする必要がある

## 変更内容

### A/B/C

v1.1のまま(変更なし)。

### D. CLI版の追加

1. **`core/native/main_cli.cpp`(新規作成)**
   - 起動引数: `QuickFolderSize_cli.exe <path>`(パス1つのみ、必須)
   - `<path>`が存在しない/ディレクトリでない場合は `{"error": "..."}` を**stderr**に出力し、終了コード `1`
   - 成功時は `scan_directory()` を同期呼び出し(進捗コールバックは使わず、完了を待つだけ)し、結果を1個のJSONオブジェクトとして**stdout**に出力、終了コード `0`
   - JSON形式は **A(JSONレポート出力)と同じスキーマ**で統一する(`path`/`scanned_at`/`total_size`/`subfolder_count`/`file_count_recursive`/`tree`)。GUIのJSONエクスポートと出力互換にすることで、AIエージェントが両方を同じパーサーで扱える
   - オプションは最小限: `--pretty`(整形出力。デフォルトはコンパクトな1行JSON、パイプ処理向け)のみ。**スコープ外(v1では実装しない)**: `--max-depth`、進捗のストリーミング出力、`--format md`(MarkdownはGUI限定のまま)
   - 管理者権限は要求しない(マニフェストを埋め込まない → 既定の実行レベル`asInvoker`。非管理者で実行された場合は自動的にWin32列挙へフォールバックする既存のengine挙動をそのまま利用するだけで、CLI側に分岐コードは不要)
   - 1回のプロセス実行につきキャッシュは持たない(`prev_cache_root = nullptr`固定)。CLIは都度フルスキャンになる(GUIのように前回結果を保持して差分再スキャンする機能はない)。これは制限事項として明記する

2. **`core/native/QuickFolderSize_cli.rc`(新規作成、任意)**
   - アイコン + `VERSIONINFO`のみ(`RT_MANIFEST`は含めない = UACを要求しない)。既存`QuickFolderSize.rc`からマニフェスト行を除いた最小版

3. **`build_native.py`**
   - GUIビルドの後に「3. CLI (`dist/binary/QuickFolderSize_cli.exe`) ビルド中」ステップを追加
   - `engine.cpp` + `main_cli.cpp`(+ 上記rcを使うなら対応する`resource_obj`)を、`-mwindows`を付けずにビルド(コンソールサブシステム、`stdout`/`stderr`が使えるようにする)
   - 出力先は`dist/binary/QuickFolderSize_cli.exe`。GUIと違い`WebView2Loader.dll`にも埋め込みHTMLにも依存しない、単体で動く1ファイル

4. **`README.md` / `README_jp.md`(仕様。ユーザー指定の記載先)**
   - 新設「## CLI」節に以下を記載:
     - コマンド書式: `QuickFolderSize_cli.exe <path>`
     - 出力: stdoutへJSON1個(スキーマはAのJSON出力と同一である旨を明記)
     - 終了コード: `0`=成功、`1`=パス不正
     - 管理者権限は不要(非要求)。ただし管理者権限で実行した場合のみNTFS MFT高速経路が自動的に使われる、という条件を明記(GUIとの違いとして重要)
     - キャッシュなし(毎回フルスキャン)である旨
     - AIエージェント向けの利用例(例: `QuickFolderSize_cli.exe C:\Users\me\Downloads | <JSONを読むツール>`)
   - 「Repository layout」の`core/native/`説明に`main_cli.cpp`を追記
   - 「Run the built app」の必要ファイル表に、CLIは単体exeで依存ファイル無し、という注記を追加

5. **`dist/documents/readme.txt` / `readme_jp.txt`(使い方。ユーザー指定の記載先)**
   - 「Required files」に`QuickFolderSize_cli.exe`を追加(**任意**の単体ツールである旨を明記。GUIの動作に必須ではない)
   - 新設「Command-line version」節: 起動方法、出力例(JSON抜粋)、終了コード、「管理者として実行しない限りMFT高速経路は使われず、通常のフォルダ列挙になる」という注意書き

6. **`document/spec_jp.md`**
   - 4節(機能一覧)にCLI版の存在を1行追記(詳細はREADME.mdへ誘導する形にし、二重管理を避ける)

### 変更しないもの(D)

- `engine.cpp`/`engine.h`本体のロジック(新しいエンジン機能は追加しない、既存APIを呼ぶだけ)

## 検証方法

1. `build.bat`実行で`dist/binary/QuickFolderSize_cli.exe`が生成されること
2. 管理者権限なしのコマンドプロンプトから `QuickFolderSize_cli.exe C:\Windows\Fonts` のようにNTFS配下の個別フォルダを指定し、UACが出ずに即座にJSONが標準出力に出ること
3. 存在しないパスを指定した場合、stderrにエラーJSON、終了コード`1`になること(`echo %ERRORLEVEL%`で確認)
4. 出力されたJSONが`JSON.parse`可能で、GUI版のJSONエクスポート(A)と同じキー構成であること
5. 管理者として実行したコマンドプロンプトから`C:\`のようなボリューム直下を指定した場合のみ、MFT高速経路が使われること(所要時間差、または`scan_mode`相当の情報で確認方法を検討)
6. `QuickFolderSize_cli.exe`単体をGUI一式(`WebView2Loader.dll`等)が無いフォルダにコピーしても動作すること(依存ゼロの確認)

## リスク

- **A/B/C**: v1.1のまま
- **D**:
  - CLIとGUIでMFT高速経路が使われるかどうかの条件(実行時の権限)が異なるため、同じフォルダを対象にしてもGUIとCLIで処理時間や`scan_method`相当の値が変わりうる。ドキュメントで明確に注意書きする必要がある(検証5で確認)
  - CLIは1プロセス1回で終了するため、GUIが持つmtimeキャッシュによる高速化の恩恵を受けられない。大きなドライブを何度もCLIで叩く用途には向かない設計であることを明記しないと、期待値のズレを生む
  - `--pretty`以外のオプションを実装しない判断が、将来的なAIエージェント側の要望(フィルタ、深さ制限など)と食い違う可能性。必要になった時点でv2として拡張する前提とする
