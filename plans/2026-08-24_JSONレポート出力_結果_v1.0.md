# 実施結果: JSONレポート出力・配布構成の見直し・CLI版追加(v1.2の実装結果)

対象計画書: [2026-08-24_JSONレポート出力_v1.2.md](2026-08-24_JSONレポート出力_v1.2.md)(v1.0/v1.1を含む)

## 実施内容

### A. JSONレポート出力

- `static/js/app.js`: `generateJsonReport()`新設、`onExportReport(format)`化、`act_report_json`のi18n・メニューハンドラ・`setReportEnabled()`の2ボタン対応を追加
- `templates/index.html`: 「レポート作成(JSON)...」メニュー項目を追加(ショートカットなし、既存の`Ctrl+Shift+S`はMarkdown版のまま)
- `core/native/webview_main.cpp`: `ShowSaveFileDialog()`に`*.json`フィルタと`SetFileTypeIndex`切替を追加、`HandleExportReport()`と`export_report`コマンド受信部に`format`パラメータを追加
- JSONスキーマ(`path`/`scanned_at`/`total_size`/`subfolder_count`/`file_count_recursive`/`tree`)は、計画書で保留していた「ノードごとに`path`を含めるか」を**含める**で確定(CLI版と完全に同一スキーマにするため)

### B. engine_x64.dllを配布から外す

- `build_native.py`からDLLビルドステップを削除。GUI・CLIとも`engine.cpp`を直接static linkするのみ
- `dist/documents/readme.txt`/`readme_jp.txt`、`document/environment.md`/`environment_jp.md`、`document/spec_jp.md`、`resources/help/help.md`/`help_jp.md`、`README.md`/`README_jp.md`から`engine_x64.dll`の記載を削除

### C. index.htmlをEXEへ埋め込む

- `build_native.py`: `bundle_html.bundle(binary_dir)`実行後に`core/native/index_embed.html`へコピーする処理を追加
- `core/native/QuickFolderSize.rc`: `IDR_INDEX_HTML RCDATA "index_embed.html"`を追加
- `core/native/webview_main.cpp`: `ReadUtf8FileToWString()`(ディスク読み込み)を削除し、`FindResourceW`/`LoadResource`/`LockResource`による`LoadEmbeddedIndexHtml()`に置き換え。`templates\index.html`への旧フォールバックコードも削除
- `.gitignore`に`core/native/index_embed.html`を追加
- `dist/binary/templates/`(旧フォールバック用コピー)の生成を`build_native.py`から削除
- 各種ドキュメントから`index.html`の必須ファイル記載を削除(配布ZIPには含めない方針に統一)

### D. CLI版の追加

- `core/native/main_cli.cpp`を新規作成。`QuickFolderSize_cli.exe <path> [--pretty] [--version]`。管理者マニフェストなし(既定asInvoker)、キャッシュなし・毎回フルスキャン、JSON出力はA(GUI)と同一スキーマ
- `core/native/QuickFolderSize_cli.rc`を新規作成(アイコン+VERSIONINFOのみ、マニフェストなし)
- `build_native.py`にCLIビルドステップを追加(`-mwindows`なし、コンソールサブシステム)
- 仕様は`README.md`/`README_jp.md`の新設「## CLI」節、使い方は`dist/documents/readme.txt`/`readme_jp.txt`の新設「Command-line version」節に記載(ユーザー指定の記載先どおり)

### バージョン統一(v2.0.1 → v2.1.1)

`core/native/QuickFolderSize.rc`、`core/native/QuickFolderSize_cli.rc`、`static/js/app.js`の`APP_VERSION`、`README.md`/`README_jp.md`、`document/about.md`/`about_jp.md`、`document/spec_jp.md`、`dist/documents/readme.txt`/`readme_jp.txt`、`HISTORY.md`/`HISTORY_jp.md`、`dist/documents/history.txt`/`history_jp.txt`を更新。`HISTORY`系は「未リリース」節をv2.1.1に統合し、今回の4項目を追記。

## 検証結果

- `build.bat`: GUI・CLIとも成功(`QuickFolderSize.exe` 3,799,124 bytes / `QuickFolderSize_cli.exe` 960,880 bytes)。`engine_x64.dll`は生成されないことを確認
- ビルド中に1件のコンパイルエラーを検出・修正: `FindResourceW`の第3引数`RT_RCDATA`がANSI版マクロとして解決され型不一致になったため、`(LPCWSTR)RT_RCDATA`へキャストして解消
- CLI版の非対話動作確認(コンソールから直接実行、GUI起動は行っていない):
  - `--version` → `QuickFolderSize CLI v2.1.1`(修正前は`wprintf`の`%s`がMinGW/UCRT環境で狭い文字列として解釈され`v2`と表示される不具合があり、`%ls`に修正して解消。同じ不具合がエラーメッセージのパス表示にもあり同様に修正)
  - 引数なし → `{"error":"usage: ..."}`をstderrに出力、終了コード`1`
  - 存在しないパス → `{"error":"path not found or not a directory: ..."}`、終了コード`1`(パスが完全な形で表示されることを修正後に確認)
  - 実フォルダ(`core/native`)をスキャン → 終了コード`0`、`python -m json`相当のパースで正当なJSONと確認、トップレベルキー(`path`/`scanned_at`/`total_size`/`subfolder_count`/`file_count_recursive`/`tree`)とtreeノードのキー構成を確認、children数もフォルダ実態と一致
  - `--pretty`出力も同様にJSONとして正しくパースできることを確認
- `dist/binary/`のRCDATA埋め込み確認: `QuickFolderSize.exe`をバイナリgrepし、最新の`static/js/app.js`由来の文字列(`generateJsonReport`、`act_report_json`)が埋め込まれていることを確認(GUI起動によるスクリーンショット確認は行っていない)
- `app.js`は`node --check`で構文エラーなしを確認
- ビルド中に、今回の変更前(過去のセッション)に生成された古い成果物(`dist/binary/engine_x64.dll`、`dist/binary/templates/`)が残っていたことに気付き、削除して整理した(現行の`build_native.py`はどちらも生成しない)
