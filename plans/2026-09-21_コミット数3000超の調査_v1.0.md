### `mcp-server` の用途と、旧フォルダーの要否（ユーザー指示 5 への回答）
- **同じ名前のフォルダーが 2 つある**:
  1. `src/integrations/mcp-server/`（追跡されている・使用中）: `QuickFolderSize_cli.exe` を HTTP の MCP ツールとして公開する Node.js の別プロセス。Claude Code などの AI エージェントが、GUI を開かずにフォルダーサイズのスキャン結果を取得するためのもの。ツールは `server_status`、`scan_folder`、`start_scan`、`get_scan_result`。`http://127.0.0.1:39391/mcp` で待ち受け、`start-admin.bat` で管理者権限で起動する（管理者でないと NTFS MFT の高速経路を使えない）。リリース ZIP にはトップレベルの `mcp-server/` として同梱される。
  2. リポジトリ直下の旧 `mcp-server/`（未追跡の残り）: v3.0.0 の置き場所。再編成でコードは 1. へ移り、いまは `node_modules`（旧・9/14）と `scan-reports`（9/14）だけが残っている。`server.js` などのコードは無く、何からも使われていない。
- **旧 `node_modules` は不要**: 新しい場所のサーバーは、自分のフォルダー（`src/integrations/mcp-server/`）から上へ向かって `node_modules` を探す。直下の旧 `mcp-server/node_modules` は探索の対象外。新しい場所には `node_modules` が無く、使うときは `src/integrations/mcp-server/` で `npm install`（`package-lock.json` は追跡済み）を実行する。
- **`scan-reports` の 3 ファイル（計 190 MB）は不要**: サーバーが実行時に自動で作る出力（`server.js` の `REPORTS_DIR`）で、`.gitignore` とリリース ZIP の作成で、意図して除外されている。9/14 の動作確認のスキャン結果（AppData\Local と WinSxS の 2 回分）で、リポジトリの文書・計画書・テストのどこからも参照されていない。WinSxS の 2 ファイルは、サイズと合計値が同じでも内容（SHA-256）は異なる、前後 2 回の試験。ローカルのユーザー名を含むパスを含む。
- 結論: 旧 `mcp-server/` は、丸ごと不要。削除はまだ実施していない（ユーザーの指示待ち）。実施する場合は、ごみ箱へ送る（戻せる）。
- 参考: この会話の開始時点で、`quickfoldersize` の MCP は ConnectionRefused（サーバーが起動していない）だった。

- 実行: 旧 `mcp-server/` を**ごみ箱へ送った**（戻せる。Shell.Application でごみ箱に `mcp-server` が 1 件あり、元の場所が QuickFolderSize であることを確認）。所要 4 秒。
- 結果: `mcp-server/` は消えた。QuickFolderSize の変更は `.gitignore` の変更 1 件と、この計画書 1 件の計 2 件。追跡ファイルの削除は 0 件。

### 対処の案（元の提示。A は実施済み）
- A（推奨）: QuickFolderSize の `.gitignore` に `mcp-server/node_modules/` と `mcp-server/scan-reports/` を追加する。ファイルは消さず、3633 件が消える。残りの 4 件は、旧レイアウトの残りとして扱う。
